# 第二轮主对话：三平台闭环与并行实现

你是本阶段唯一主控。读取 AGENTS.md、docs/STATUS.md、docs/TASK_BOARD.md、docs/DECISIONS.md、docs/ARCHITECTURE.md、docs/CONTRACTS.md、docs/SPEC.md、docs/ACCEPTANCE.md，然后从当前真实代码和证据继续。

## 先检查前提

核对第一阶段的原文、图片及数据契约证据。没有验证的字段和状态不要默认为正确。阻塞时先解决，或把不依赖阻塞的工作明确划分出来；未经实测的数据契约不得被标为最终冻结。

确认当前分支与工作区，统一依赖、共享数据契约、任务状态和 API 输入输出，并建立干净基础提交。将接口入口与安全边界由你负责，避免子任务分别设计接口。

## 并行分工

使用真实子智能体，最多同时三个。先由你建立三个不同 Git worktree 和分支，登记绝对路径、基准提交、数据契约版本与可写路径，再委派：

1. ima_engineer：完成 src/server/ima 与 tests/ima；包括正确分页、目录回退、型号解析依据、原文/图片访问方式、来源归一化、过期或不可用访问方式处理、明确错误分类。
2. workflow_engineer：完成 src/server/workflow、llm、verification、prompts/runtime 和 tests/workflow；包括澄清、场景策略、受事实包约束的生成、逐项核验、平台要求、修改后重验和失败状态。
3. ui_engineer：完成页面与组件（排除 src/app/api）、样式和相关界面检查；展示场景判断、依据、图文、核验四部分，支持三平台、修改和导出。开发假数据必须可辨认，正常模式不能回退为假结果。

每个任务使用 prompts/DELEGATION.md 格式，明确入口函数和实际数据契约。worker 不修改共享数据契约、根依赖/锁、主控状态，不递归派生其他智能体。数据契约不足时先报告，由你修订并通知受影响任务。

如当前环境无法创建独立 worktree，将实现任务顺序执行；仍可并行只读调查，不允许多人同时改同一 checkout。

## 主控负责

- src/contracts 的唯一数据结构与运行时验证。
- src/app/api 的任务、修改、资产、导出和连接状态接口。
- src/server/assets 的服务端原件获取及受控预览；禁止任意 URL 代理、秘密下发或无依据型号标记。
- src/server/runs 的修订和持久运行记录。可发布标记必须绑定具体文本、事实、图片及核验版本。
- 所有依赖及锁文件，基础运行配置和模块集成。

先审查 worker 的 diff 是否在分配范围内，再逐一集成其提交。集中解决边界错误，记录数据契约或架构变化。集成完成后在主控版本验证完整流程。

## 必须完成的业务表现

- 针对缺失关键信息追问；信息足够时直接执行。
- 同一型号换人群/场景，主要问题、卖点顺序、图片选择理由发生合理变化。
- 同一任务换平台，标题、结构、语气、配图数量与行动引导变化；公众号2—4、小红书3—6、朋友圈1—3张，图片必须真实可用。
- 参数和功能只用指定库依据，保留限制条件，逐条绑定出处；型号或资料冲突停止成稿。
- 无依据价格、补贴、销量、奖项、个人体验和用户评价不进入文案。
- 修改后创建新修订并重新核验；旧通过状态不继承。
- 图片缺失、模型或 ima 不可用、访问权限不足都有清楚的状态；不能发布“已核验”但事实上不完整的结果。
- 复制或导出核验通过的最终文本、图片说明及位置，同时保留核验信息。海报未实现时明确列入待办。

## 验证与交接

根据实际风险执行数据契约/类型检查、关键业务测试、构建以及有价值的浏览器完整流程检查。只在确有依赖变化时重新安装，不反复跑无关检查。

用真实账号和实际模型做最少一条完整 live 流程，并检查三个平台及修改后的状态；缺少凭证时记录 BLOCKED，合成结果不能冒充。

更新 STATUS、TASK_BOARD、DECISIONS、README 和可追溯提示词。回报集成提交、真实验证、未解决问题，并为第三轮留下稳定基准，不把“代码已写”当作“实际可用”。
