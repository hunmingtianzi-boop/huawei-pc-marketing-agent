## 第一阶段确认与新增决定（2026-10-18）

- D01/D02/D03/D09 确认：一个主控，两个真实只读子任务，最多3个子智能体；阶段一只有主控写代码。根目录无提交时先导入规则并建立本地 Git 基线，分支 codex/foundation；并行编码 worktree 留待第二阶段实际创建。
- D05 确认：无现有应用，采用 Next.js 16.4.2 / React 19.3.1 / TS 5.9.3，Node 最低20.9，实测26.0；单一 npm 锁文件。根据官方 Next 安装文档和实际 registry/engines 核实。没有为了初始化覆盖源资料。
- D04 从“必须实测”改为已验证的接入边界：指定库+原文+型号图片七步 live PASS，映射按 CONTRACTS 第10节冻结为1.0.0，代码554ddba。产品、图片键一致；完整业务运行 schema 仍需阶段二主控先补齐后委派。
- D10：用户截图定位到 Downloads 协作开发包，安全解压到当前根；保留已有资料和 STATUS，再用最终状态替换早期阻塞记录。原始完整知识库、设计参考和PDF均不入公开源码。
- D11：ima 只用4个只读 wiki 接口。官方 SDK 在隔离子进程调用：凭证仅内存/明确环境，固定官方目标、禁止重定向、上层请求/进程/总预算，远端更新上下文不透传不执行；不改官方源码或伪造版本检查。
- D12：实测搜索返回无分页，目录有包装、type99及多个同名型号。按真实面包屑核对类型，仅搜索接受无两个分页字段的单响应；歧义/空搜索走P1受限目录。未识别结构保持显式失败。
- D13：当前产品事实原文H1含明确鸿蒙版与编辑后缀，无内嵌图；使用同型号图片索引CSV明确型号/文件名/尺寸，再从ima images目录取图。引入csv-parse处理BOM/引号；索引外部URL不用。相近型号、歧义记录、路径、尺寸、解码均有门槛和回归。
- D14：仅做本机单用户回环服务；Host/Origin限制和UUID资产检查不宣称是公网多用户认证。SDK/私有数据不参与构建文件追踪，需实际文件系统部署；未制作云端独立包。
- D08 保持：未假定模型提供商或可用型号；LLM变量仅为后续服务端配置。账号昵称未被API验证，不从本地别名伪造身份。
- D06/D07 保持第二阶段范围：三平台策略/核验/修订/导出及平台完整图数尚未实现。本次一张图只用于G1，不代替完整图文和比赛材料。

凭证由用户提供并授权本机调用，仅写入被忽略且0600的.env.local；不记录值、片段、长度或凭证哈希。规则自动加载与自定义角色选择能力未独立证明，当前按可调用的真实子工具显式传入角色全文约束。
