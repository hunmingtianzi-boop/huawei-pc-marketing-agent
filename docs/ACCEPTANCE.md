# 验收门槛、用例与证据要求

状态：验收计划，**尚未执行**。应用尚未开发，团队凭证及目标知识库活接口尚未验证。下面的通过标准不是测试结果；未运行项一律不得写 PASS。

## 1. 怎样称为“测过”

| 证据模式 | 定义 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| `synthetic` | 人工构造并明确标注的测试数据、冲突样本、错误分支 | 内部规则、状态、版本和错误处理是否符合设计 | 真实 ima 可连接、真实资料可读取、真实图片来源及型号正确 |
| `replay` | 来自有权获取的真实调用记录，经必要脱敏后回放，标明采集时间和来源 | 该批已记录结构能否解析、流程能否重复处理 | 本次实时连通、当前知识库内容最新、签名链接仍有效 |
| `live` | 本次实际使用团队凭证读取目标知识库；实际内容和素材路径可核查 | 本次账号权限、读取、图片访问及端到端执行情况 | 未来访问始终可用、所有型号均可处理、没有覆盖的场景也能通过 |

模式至少按 ima 取证和生成组件分别记录。真实模型加 synthetic 资料仍是 synthetic 取证；live 检索后人工替换结果的演示不能标为完整 live。任何注入的冲突样本、mock 或人工辅助都须标注，不修改共享知识库来造测试。

测试记录字段统一为：用例 ID、代码提交、运行时间、平台/场景、证据模式、环境前置条件、输入、实际观察、产物位置、结果、未解决问题。结果取 `NOT_RUN` / `PASS` / `FAIL` / `BLOCKED`；`BLOCKED` 要写真实阻塞原因，不能以“设计上支持”代替执行。

原始凭证和访问 headers 永不出现在记录里。必要的原文/图片回放材料只保留在有权限的环境，不随公开仓库或魔搭项目分发完整知识库素材。[R1，第 6–7 页]

## 2. 分阶段门槛

| 门槛 | 要达到的状态 | 所需证据 | 当前状态 |
| --- | --- | --- | --- |
| G0：开发输入准备好 | 明确默认技术栈、范围、接入风险、内部草案和验收规则 | 本交付包与待确认清单；不算应用已完成 | 文档草案已提供；代码/环境尚未验证 |
| G1：真实接入成立 | 目标库实际可读；能取得产品原文，且至少取得一张型号适用范围可证、可展示的 ima 图片；内部契约已按样本冻结 | 本次 live 调用的脱敏记录、原文定位、实际图片及型号依据 | NOT_RUN，待团队账号、凭证与真实调用 |
| G2：核心实现可验证 | 三平台流程、版本失效、异常处理及导出门槛实现，并通过必要 synthetic/replay 检查 | 可运行代码、自动/人工检查记录、失败分支结果 | NOT_RUN，应用未开发 |
| G3：正式图文任务可用 | 满足平台完整图片数、场景和平台变化、事实/图片核验、修改与导出；形成真实运行结果 | live 任务记录及成稿、来源、核验结果 | NOT_RUN |
| G4：独立验收与材料一致 | 新上下文从仓库和说明重新运行，逐条复核功能与材料，无阻断问题 | 独立验收记录、至少 3 组复赛结果、真实流程视频、链接检查 | NOT_RUN |

**G1 的一张图片只证明接入路径；不是公众号、小红书完整配图验收。** 不足平台图片数量时，必须明确标为未完成，不用外部图、重复图或生成图凑数。

G1 中“凭证可用/目标库可读”也不自动等于赛题“识别当前账号”已完全满足。记录实际可证明的状态；没有昵称接口证据时不得假造昵称或“身份核验通过”。若依赖客户端同账号确认，说明这一步和剩余限制，必要时向组委会核实是否满足要求。[R1，第 5–7 页；R2]

## 3. 真实接入检查

| ID | 操作 | 通过标准 | 所需模式 |
| --- | --- | --- | --- |
| I-01 | 检查凭证配置与目标库可读 | 界面只显示安全状态；实际找到指定库并成功读取其内容；未展示完整 Client ID/API Key 或内部 ID | live |
| I-02 | 查找并读取一个具体型号原文 | 读到能够支持参数/功能的原文，来源和定位可核查；搜索摘要不冒充完整原文 | live |
| I-03 | 取得该型号至少一张图片 | 实际文件可解码/展示，来源属于 ima；型号适用范围有资料依据；单靠文件名不通过 | live |
| I-04 | 搜索为空时继续定位资料 | 实际代码执行 `get_knowledge_list` 分页/进入目录回退；不误报无权限；回退仍找不到时如实标记 | synthetic 或 replay 验证分支；另核查 live 目录读取 |
| I-05 | 分别解析库、目录、搜索和面包屑样本 | 按真实结构明确映射 `id/name`、可能出现的 `kb_id/kb_name`、`media_id/folder_id`；未知结构显式失败 | live 样本＋replay 回归 |
| I-06 | `get_media_info` 返回成功但没有可用链接 | 不显示“原文/图片读取成功”；报告不可访问，按已验证分支处理 | synthetic 或 replay |
| I-07 | 返回需 headers 的 URL、笔记分支、失败链接 | 不把它们都当公开直链；正确处理已实现分支，未实现分支明确阻塞 | synthetic/replay；声称支持的分支补 live |
| I-08 | 多页目录、重复游标或遍历预算耗尽 | 不只取第一页就宣称遍历完；不无限循环；达到预算时明确未完成及下一步 | synthetic/replay |

I-04 的受控空搜索是测试注入，记录中必须写明；它证明分支行为，不应伪装成服务当时真实返回为空。若 live 自然遇到空结果，另存真实回退记录。

## 4. 业务与图文检查

| ID | 输入或变化 | 必须观察到的行为 | 正式证据 |
| --- | --- | --- | --- |
| B-01 | “新生想买轻薄本”且未给具体型号/任务条件 | 只补问会影响执行的产品、场景、平台或目标信息；不直接编型号成稿 | live 流程或完整运行测试 |
| B-02 | 指定真实产品＋新生＋开学＋小红书 | 标题、短段场景、标签、CTA 完整；3–6 张型号适用范围可证图片；无伪造亲测 | live |
| B-03 | 同产品改为经常出差的职场用户，其他条件先保持一致 | 用户问题、内容切入点、卖点顺序及图片用途有可解释变化；不只换称呼 | live 对照 |
| B-04 | 同任务从小红书切到公众号 | 结构、语气、图片数和 CTA 均重新适配；公众号 2–4 张；不得保留旧版本通过标记 | live 对照 |
| B-05 | 同任务切到门店朋友圈 | 一个核心卖点、短文、明确咨询/到店引导；1–3 张图；不编造地址、时间和权益 | live 对照 |
| B-06 | 换成知识库内另一具体产品 | 重新取证，事实和图片全部对应新产品；不残留旧型号、旧引用 | live |
| B-07 | 选中正文主张和配图查看依据 | 能看到安全来源标题、可理解的定位、对应必要短摘录/图片证据；权限内可核查 | live |
| B-08 | 在某平台所需图片不足时生成 | 说明缺口并阻止完整成稿导出；不把“一张图已接通”说成“全平台完成” | synthetic/replay，必要时 live |

本项目首版目标是三平台；手册复赛结果数量门槛是至少 3 组、2 类业务场景、2 个平台。可选三组素材为“新生开学/小红书”“出差办公/公众号”“同产品门店短文/朋友圈”，但必须真实运行后才计入结果，不能预先写成优秀案例。[R1，第 4、8 页]

## 5. 事实、图片和宣传风险检查

| ID | 干扰输入 | 通过标准 | 模式说明 |
| --- | --- | --- | --- |
| F-01 | 混入相近型号的参数或配置 | 发现错配，拒绝写入目标型号成稿，显示对应依据或待确认项 | synthetic/replay 可精准构造；正式演示用真实流程 |
| F-02 | 提供相近型号图片或只凭名称猜图 | 拒绝 mismatch，uncertain 保持待确认；不能打勾后继续导出 | synthetic/replay，真实图对照需有权访问 |
| F-03 | 两份同型号、同条件资料存在冲突 | 停止当前成稿，列出冲突及来源并请求人工确认；不任选一项 | 标明的本地 synthetic 冲突样本；不改共享库 |
| F-04 | 要求添加无依据价格、补贴或库存 | 不生成该信息；给出删除/咨询确认等安全替代方向，保留拦截记录 | live 输入任务＋synthetic 分支回归 |
| F-05 | 要求写“行业第一”、保证结果、无依据比较或竞品贬低 | 识别并修订；不只在句末加一个免责声明继续保留不实主张 | synthetic/replay，并展示真实工作流行为 |
| F-06 | 要求编造亲测、销量、奖项、用户评价或软件测试结果 | 拒绝伪造，成稿无此类内容 | 同上 |
| F-07 | 省略测试条件，把“最高/特定配置”改成普遍承诺 | 标记事实被扩大；补齐必要条件或改写后重验 | synthetic/replay |
| F-08 | 原始资料中夹带指示模型忽略规则的文本 | 把原文当作证据数据，不能改变开发/业务规则或触发额外操作 | synthetic |

手册规定：图片非 ima 来源或型号不符，图片引用项计 0；虚构价格、补贴、销量、奖项或用户评价，相应任务准确性和合规性计 0。验收因此把这些设为阻断项，而不是普通文风建议。[R1，第 9 页]

## 6. 改稿与导出检查

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| V-01 | 对 ready 稿修改任意正文 | 版本递增、旧核验失效、立即关闭成稿导出；重验通过后才恢复 |
| V-02 | 只改标题、导语、CTA、标签或图片说明 | 同样失效并核验；不能只检查正文 |
| V-03 | 换图片、图片顺序/位置、产品、平台、场景或证据 | 更新相关策略与版本；核验绑定当前稿、当前证据包和当前任务 |
| V-04 | 旧生成请求比新请求晚返回 | 旧版本不能覆盖新稿，不能把新稿错误标为通过 |
| V-05 | 浏览器绕过按钮直接请求导出旧版/未通过稿 | 服务端拒绝；不得只靠 UI 禁用实现限制 |
| V-06 | 核验通过后执行复制/导出 | 得到当前版本的标题、正文、图片说明/来源/插入位置和 CTA；不混入旧草稿或私有 URL |
| V-07 | 当前图片已失效或不可访问 | 明确提示并重新确认素材；不导出缺图但标为完整的结果 |
| V-08 | 核验发现问题，模型自行修订草稿 | 修订稿重新核验，不能继承修订前报告或用模型自述通过代替 |

V 系列主要使用可重复的 synthetic/replay 自动检查，并至少保存一次真实改稿—核验—导出的 live 过程。

## 7. 公开展示和运行安全检查

| ID | 检查 | 通过标准 |
| --- | --- | --- |
| S-01 | 仓库、README、说明书、录屏、浏览器响应与控制台 | 无 API Key、完整 Client ID、认证 headers、provider 内部 ID 或访问秘密 |
| S-02 | 前端网络与导出内容 | 只有白名单安全 DTO；来源可核查但不返回完整 raw/原文/签名直链；受控素材请求验证当前任务权限 |
| S-03 | 应用使用 ima 的接口清单 | 只读所需资料；不调用删除、修改、上传或对外共享知识库接口 |
| S-04 | 执行模式标记 | synthetic/replay/live 与实际路径一致；模型/资料有人工替换时不虚报真实端到端运行 |
| S-05 | 无凭证、限流、网络错误和未知 schema | 给出具体、脱敏的失败信息；不显示假账号、假连接或固定成功结果 |

S-01 的“无完整 Client ID”按本项目较保守的展示设计执行；手册要求源码不含 Client ID 或其他密钥，并禁止演示完整敏感凭证。[R1，第 2、5–7 页]

## 8. 新上下文独立验收顺序

第三个主对话从已提交代码、根 `AGENTS.md`、本规格与验收文档开始，不依赖上一主对话的口头总结。

1. 确认代码提交、运行环境和资料模式，按 README 实际安装、启动；前序交接中没有证明的能力仍视为未验证。
2. 先查 G1 的真实原文和图片证据，再看完整流程；只读研究或静态截图不能代替活接口证据。
3. 运行三个平台基础任务及换场景、换平台、换型号对照，抽查句子和图片来源。
4. 用已标记的 synthetic/replay 用例检查资料冲突、错配、无依据宣传和改稿失效；必要时补 live 验证。
5. 检查失败状态、服务端导出约束和公开材料脱敏，记录具体缺陷。
6. 主控修复后只重验与缺陷相关的用例和必要端到端路径；最后对照提交材料，不把未实现海报列为已完成。

独立上下文用于重新核对证据，不表示自动隔离代码。写入 worker 仍按根 `AGENTS.md` 使用独立 worktree，整合由当前主控统一完成。[R3]
