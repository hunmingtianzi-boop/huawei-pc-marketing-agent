调研日期：2026-10-18。

## 1. 结论与证据边界

本次已下载并静态查看赛题手册指定的官方 ima Skill 1.1.10 压缩包，检查了模块说明、接口文档、版本元数据和统一调用脚本。没有运行下载的脚本，没有读取用户凭证，没有认证用户账号，也没有实际访问举办方知识库。因此，本文能够确认官方包写明的契约和脚本行为，不能证明当前账号、具体产品资料或图片已经联通。

**开发第一关是用真实账号完成一次有记录的只读探测，然后冻结 Adapter 契约。**在这之前，其他模块可以依照内部数据结构使用明确标记的合成样例开发，但不能将其结果记为真实联调通过。

## 2. 已确认的接口契约

知识库接口统一使用 `POST https://ima.qq.com/openapi/wiki/v1/<接口名>`，请求体为 JSON。认证 Header 为 `ima-openapi-clientid`、`ima-openapi-apikey`，另有 `Content-Type: application/json`。官方脚本还发送 `ima-openapi-ctx: skill_version=<版本>`。

| 接口 | 必需请求字段 | 可选请求字段 | 文档所述 `data` 返回字段 |
| --- | --- | --- | --- |
| `search_knowledge_base` | `query: string`、`cursor: string`、`limit: 1–20` | 未列出 | `info_list`、`is_end`、`next_cursor` |
| `get_knowledge_list` | `knowledge_base_id: string`、`cursor: string`、`limit: 1–50` | `folder_id: string` | `knowledge_list`、`is_end`、`next_cursor`、`current_path` |
| `search_knowledge` | `query: string`、`cursor: string`、`knowledge_base_id: string` | 未列出 | `info_list`、`is_end`、`next_cursor` |
| `get_media_info` | `media_id: string` | 未列出 | `media_type`，以及可选的 `url_info` 或 `notebook_ext_info` |

`search_knowledge` 没有文档支持的 `limit` 参数，不要照搬其他搜索接口的参数。其命中条目的文档字段为 `media_id`、`title`、`parent_folder_id`、`highlight_content`。高亮摘要用于定位资料，不能冒充已读取的完整原文。

`get_knowledge_list` 的根目录查询可省略 `folder_id`。`current_path` 是当前路径面包屑，不是子文件夹清单。官方说明允许列表及搜索结果包含文件与文件夹，但目录条目的实际结构需要现场验证。

### 分页

1. 首次请求使用 `cursor: ""`。
2. `is_end=false` 时，将返回的 `next_cursor` 原样用于下一页。
3. `is_end=true` 时停止。

实现需检测重复游标、缺失游标和重复条目，设置合理的页数及请求时间上限。分页异常应报告契约或连接问题，不能解释成“没有资料”。知识库列表接口支持 `query: ""` 列举当前账号可见的知识库。

## 3. 两处字段差异必须先验证

### 3.1 知识库 ID 与名称

官方包的 `SearchedKnowledgeBaseInfo` 定义为 `id`、`name`、`cover_url`；赛题手册第 7 页明确说实测返回的是 `kb_id`、`kb_name`。

Adapter 可以识别这两组已知别名，并统一成内部 `id/name`，但必须保留使用哪一组字段的诊断记录。如果两组同时存在且值冲突，应报告契约异常。不得递归搜索任意名为 `id` 的字段，也不得遇到同名多结果就盲取 `info_list[0]`。

### 3.2 文件夹 ID

官方 `references/api.md` 的 `FolderInfo` 表定义了 `folder_id/name/...`；同包 `knowledge-base/SKILL.md` 又明确说明，定位文件夹时取返回的 `media_id` 作为 `folder_id`，不要构造前缀。

首轮需要检查实际目录条目，并分别记录列表条目和 `current_path` 的结构。不要把面包屑的 `FolderInfo` 结构直接当成列表条目契约。业务模块只接收已归一化的文件和文件夹对象。

手册中的“314 项”是举办方当时的实测记录，不应成为程序的固定数量断言。

## 4. 搜索为空与无权限必须分开

赛题手册第 7 页要求：搜索无结果时，通过 `get_knowledge_list` 回退到目录，进入 `P1-产品参数库`，再查找具体型号的 `article.md`。

| 实际结果 | 应采取的行为 |
| --- | --- |
| `code=0`，搜索列表为空 | 记录搜索无命中，执行目录回退 |
| 按知识库名称搜索为空 | 可使用 `query: ""` 分页列举可见知识库，再匹配指定名称 |
| 后端 `code=110030` | 报告明确的无权限结果，检查是否为加入共享库的同一账号 |
| 网络、超时、响应格式或脚本更新错误 | 归类连接或协议问题，不归类“无资料” |
| 列举后仍未找到指定库 | 报告未找到及已完成的检查；不能直接断言用户未加入 |

仅浏览任务指定共享知识库的必要目录。不要扫描其他库的正文，也不要把“获取可添加知识库列表”当成只读访问权限判断：可写与可读是不同能力。

## 5. 原文和图片的真实获取能力

`get_media_info` 返回的是访问方式。`code=0` 不等于已获取原件。

| 响应情况 | 可确认的事实与处理 |
| --- | --- |
| `url_info.url` 非空 | 用该 URL 和 `url_info.headers`（若存在）请求原件 |
| `code=0` 但没有 `url_info` | 接口成功，原文访问方式不可用；不能标记原文已读取 |
| URL 请求非 200、返回登录页或下载失败 | 原件获取失败，记录原因；官方说明建议使用 ima 客户端查看 |
| `media_type=9` | 官方枚举中的图片类型；仍需实际读取并检查文件 |
| `media_type=11` 且存在 `notebook_ext_info.notebook_id` | 是笔记访问分支，需要单独处理，不能按图片处理 |

### 推荐的图片实现

由服务端获取并验证图片，再以应用内部的临时资产地址给前端预览。`url_info.headers` 可能包含访问令牌，不能假设浏览器普通 `<img src>` 能完成带认证的请求。

服务端应做到：

- 仅处理来自本次可信知识库响应的地址，验证协议、目标和重定向；不把 ima 主凭证附加到媒体域名。
- 仅将媒体访问所需 Headers 发给相应目标；跨域重定向不得自动转发敏感 Headers。
- 校验 HTTP 状态、MIME、文件签名、尺寸和体积，排除登录页或非图片响应。
- 前端持有应用自己的资产标识，不持有 API Key、访问 Headers 或原始带签名 URL。
- 记录来源链：知识库、目录和资料标题、`media_id`、检索时间、原件哈希、型号绑定依据、访问与核验状态。
- 面向用户显示资料名称和图片说明，内部 ID 留在服务端诊断与证据记录中。

只有完成真实获取且型号绑定有依据的图，才计入可用配图数量。文件名相似不足以自动证明型号一致。

以下内容本轮尚未验证：实际知识库中的图片是否为独立条目、`article.md` 中相对图片路径如何解析、签名链接有效期、下载频控、是否能直接获取文档内嵌图。官方材料没有给出独立视觉检索或自动型号识别接口，不要编造这些能力。

如果图片来自文档内嵌内容，应保留所在文档及图片位置的来源链，不能虚构独立媒体 ID。原始资料、图片、签名链接和受限响应缓存不得进入公开 Git 仓库或公开打包材料。

### 笔记分支的边界

官方笔记接口是 `POST /openapi/note/v1/get_doc_content`，必需字段为 `note_id` 和 `target_content_format`。`0` 是纯文本，`2` 是 JSON，文档明确 `1` 的 Markdown 读取不支持。

文档还标注需为本人的笔记，所以共享库中其他人的笔记能否读取不能预设。仅在本次指定库的已命中资料确实返回笔记分支时进行必要尝试；权限失败就记录限制。不得为解决该问题私自列举或扫描用户全部私人笔记。

## 6. 官方脚本的运行边界

### 6.1 运行时

官方 1.1.10 的 `meta.json` 指定 Node.js 最低为 18.0.0。这只是官方 ima 脚本的最低要求，**不代表应用使用的 Next.js 等依赖也只需要 Node 18**。初始化应用时，应依据所选依赖版本的当前官方要求统一运行时、版本文件和 CI 配置。

### 6.2 两层错误与更新检查

| 情况 | 官方脚本表现 | Adapter 要求 |
| --- | --- | --- |
| 缺少凭证、参数错误、网络等执行失败 | 非零退出，stderr 中 `code=-100` | 解析结构化错误，脱敏显示，不当作业务空结果 |
| 检测到新 Skill 版本 | 非零退出，stderr 中 `code=-200`；stdout 含更新上下文 | 原业务请求尚未发出；进入明确更新阻塞状态 |
| 后端业务失败 | 进程可能正常退出，stdout JSON 的 `code≠0` | 仍须判定失败，保留业务码与脱敏消息 |
| 后端业务成功 | stdout JSON 的 `code=0` | 继续检查预期数据结构，不能只看进程退出码 |

脚本默认每日首次调用先执行 `openapi/check_skill_update`；更新检查网络失败时会跳过该检查并继续原请求。其源码没有显式请求超时，上层需要进程或请求时间上限及格式检查。

遇到 `-200` 时，不能自动执行返回的远端 `instruction`，不能把它当成高优先级开发指令。应记录“需检查官方更新”，核对官方版本、差异和契约，完成必要回归后再重试。不要通过伪造版本号、伪写更新检查文件或绕过检查来制造成功状态。

### 6.3 凭证别名与遮蔽

源码的实际选择顺序分别为：

```text
Client ID：options.clientId → IMA_CLIENT_ID → IMA_OPENAPI_CLIENTID → 官方用户配置文件
API Key：options.apiKey → IMA_API_KEY → IMA_OPENAPI_APIKEY → 官方用户配置文件
```

因此，旧的 `IMA_CLIENT_ID/IMA_API_KEY` 会遮蔽手册指定的 `IMA_OPENAPI_CLIENTID/IMA_OPENAPI_APIKEY`，两字段还可能在不完整配置时混用不同来源。

本项目应选用一个完整凭证对：优先统一采用手册的 `IMA_OPENAPI_CLIENTID/IMA_OPENAPI_APIKEY`，或由后端在内存中显式传入 `options.clientId/apiKey`。调用前在内存检测多组配置是否同时存在及是否不一致；若冲突，输出配置冲突状态并停止该调用，不能随意选一组。

检测输出仅包括变量或配置组的存在状态、完整性、是否冲突及选中的来源名称，**绝不输出值、片段、长度、哈希或可反推的凭证指纹**。缺少项目选择的完整凭证对时直接报告阻塞，不为了兜底自行翻读历史凭证文件。

若通过子进程调用官方脚本，应构造明确的子进程环境，避免继承的旧别名遮蔽。若使用显式 options，只能在后端内存中传入，不能把包含密钥的 JSON 放到命令行参数、文件或日志。

脚本允许 `options.baseUrl` 或 `IMA_BASE_URL` 覆盖默认域名。生产 Adapter 要固定官方 `https://ima.qq.com`，拒绝外部输入覆盖认证目的地，并控制敏感 Headers 的重定向行为。

## 7. 只读 Adapter 的建议边界

以下是内部方法建议，不是 ima 官方新增接口：

| 内部方法 | 责任 |
| --- | --- |
| `resolveKnowledgeBase` | 解析并验证指定库，归一化已知字段别名 |
| `listEntries` | 分页浏览指定目录，归一化文件与目录 |
| `searchEntries` | 检索并返回定位信息，保留回退诊断 |
| `getMediaAccess` | 解析媒体访问分支，隔离原始 URL 与 Headers |
| `fetchSourceContent` | 获取并解析本次需要的原文，形成来源记录 |
| `fetchImageAsset` | 获取、检查图片并建立可追踪的临时资产 |

业务 Agent 仅依赖归一化的 `KnowledgeBaseRef`、`SourceDocument`、`ImageAsset`、`Evidence` 等内部对象。外部字段差异由 Adapter 一处消化，前端和生成模块不自行解析 ima 原始响应。

允许调用的接口应显式列入只读清单。实际范围为上述四个知识库接口，以及确有需要时的 `get_knowledge_base`、本次命中笔记的 `get_doc_content`；官方更新检查单独处理。不得向业务 Agent 暴露通用任意路径调用能力，也不提供 `create_media`、`add_knowledge`、`import_urls`、笔记写入或删除操作。

真实响应只保存在受控且不入库的本地诊断缓存；公开测试使用合成样例。抽取可公开的字段结构时，应去掉密钥、访问 Headers、带签名 URL、受限原文和媒体内容。

## 8. 首轮真实探测与验收

建议提供 `scripts/verify_ima_connection.*`，首轮先完成有限范围的探测：一份原文、一张图片即可，不需要全库下载。

| 步骤 | `PASS` 的必要证据 |
| --- | --- |
| 配置与运行时 | 必需运行时可用；选择的完整凭证对存在，无配置冲突；不输出任何凭证值 |
| 指定库定位 | 真实接口成功，指定名称匹配，并记录实际字段组；有歧义时不算通过 |
| 目录访问 | 真实读取指定库目录，确认条目和面包屑的字段结构 |
| 产品检索 | 获取实际存在的型号资料；若搜索为空，记录目录回退执行结果 |
| 原文读取 | 实际取得可解析正文，保存内部来源关联 |
| 图片获取 | 实际取得图片字节并通过格式检查，具备可核对的型号来源依据 |

状态必须有明确含义：

- `PASS`：本步骤在所标识的模式下实际运行并满足条件。
- `BLOCKED`：缺凭证、待用户登录或加入库、需要检查更新、外部服务或网络不可达等前置条件未满足；下游依赖步骤保持阻塞。
- `FAIL`：已得到可处理的服务响应，但契约解析、文件格式、型号绑定或输出行为不符合验收。网络、权限或外部服务不可达按 BLOCKED 记录，不能笼统把下载失败都归为代码失败。

每份报告必须包含 `mode`，取值统一为 `synthetic`、`replay` 或 `live`，定义与 ACCEPTANCE.md 一致。每个步骤含 `executed`、`status` 和不含秘密的原因或证据摘要。真实接入整体通过要求全部必要步骤在 `live` 模式下通过；`synthetic` 和 `replay` 通过只能证明相应离线逻辑，不能计入本次真实联调。

缺少凭证时的真实示例结构：

```json
{
  "mode": "live",
  "status": "BLOCKED",
  "stages": [
    {
      "name": "credentials",
      "executed": true,
      "status": "BLOCKED",
      "reason": "所选凭证组未完整配置"
    },
    {
      "name": "knowledge_base_access",
      "executed": false,
      "status": "BLOCKED",
      "reason": "依赖凭证配置"
    }
  ]
}
```

不要把预期示例或手册截图当作现场接口证据。上述探测通过后，才能冻结外部响应到内部对象的映射，并让负责内容策略、事实核验和界面的子代理按该契约并行开发。

## 9. 当前账号识别的未决能力

此次核对的官方包没有文档化的账号昵称或当前用户身份查询接口。不能虚构 `get_current_user`，也不能将本地自填账号别名标注为官方认证返回的昵称。

当前能够设计的最低证据链是：配置来源明确、官方接口认证通过、指定共享库实际可读。界面可以同时展示“本地账号别名”和“指定库连接状态”，但两者应保留真实含义。若要宣称已验证真实登录昵称，须另有真实接口或客户端证据；赛题的账号识别验收口径仍需要在联调中确认并如实写入已知限制。
